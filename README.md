# 微信求职信息提取器 (WeChat Job Extractor)

从**微信公众号招聘推文**里一键提取结构化求职信息，重点是**官方投递链接**。

银行/央企/国企的校招推文普遍是「标题党 + 长图 + 阅读原文跳转」的结构，真正要用的信息（投递入口、截止时间、岗位、专业）散在正文各处，甚至只印在图片里。这个插件把能自动化的部分自动化：**打开文章 → 右下角点一下 → 投递链接、截止时间、招聘主体全部列出来，可直接复制或导出。**

```
┌─ 提取结果 ─────────────────────────────┐
│ 招聘主体   中信银行                     │
│ 招聘批次   2027届                       │
│ 投递截止   2026-10-09                   │
│ 学历要求   本科（本科及以上）            │
│ 投递入口   https://job.citicbank.com    │  ← 自动解开 /mp/redirect 中间页
│ 阅读原文   https://job.citicbank.com/   │
└────────────────────────────────────────┘
```

## 一、安装

### 方式 A：Chrome / Edge 扩展（推荐，功能最全）

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录 `wechat-job-extractor/`
4. 打开任意 `https://mp.weixin.qq.com/s/...` 文章，右下角出现绿色按钮即成功

> 打包版：`dist/wechat-job-extractor-v1.0.0.zip`，解压后再按上面 3 步加载。

### 方式 B：油猴脚本（零安装成本，Chrome/Edge/Firefox 通用）

1. 先装 [Tampermonkey](https://www.tampermonkey.net/) 或 Violentmonkey
2. 三种装法任选：
   - **一键安装（推荐）**：浏览器打开 [`dist/wechat-job-extractor.user.js`](https://raw.githubusercontent.com/FeC3-pearlite/wechat-job-extractor/main/dist/wechat-job-extractor.user.js)，Tampermonkey 会自动弹出安装页
   - **从仓库安装**：在 Tampermonkey 里新建脚本 → 粘贴该文件内容 → 保存
   - **本地安装**：直接用本目录 `dist/wechat-job-extractor.user.js`
3. 打开微信文章页，右下角同样会出现提取按钮

脚本已配置 `@updateURL`，之后我更新仓库时 Tampermonkey 会自动提示升级。

两种方式共用同一套提取引擎（`src/core/`），结果完全一致。

> 项目地址：https://github.com/FeC3-pearlite/wechat-job-extractor

## 二、怎么用

| 入口 | 说明 |
| --- | --- |
| 页面右下角悬浮按钮 | 打开文章后点「🔍 提取招聘信息」 |

## 三、能提取什么

| 字段 | 抽取方式 | 典型输出 |
| --- | --- | --- |
| **投递入口** | 正文外链 + 纯文本 URL + 「阅读原文」三路汇总，按域名/锚文本打分排序 | `https://job.citicbank.com` |
| **阅读原文跳转** | `msg_source_url` → 底部栏 `<a>` → 锚文本含「阅读原文」 | `https://eoap.cebbank.com/...` |
| 招聘主体 | 标题模板直取 → 公众号名 → 全文候选加权 | `中信银行`、`中国光大银行` |
| 招聘批次 | `2027届` / `2027年校园招聘` / `面向2027年` | `2027届` |
| 招聘类型 | 秋招 / 春招 / 校招 / 社招 / 暑期实习 | `秋季校园招聘` |
| **投递截止** | 「截止/报名/网申」上下文词附近取日期；只有「10月25日」时按**发布时间**补全年份并标「待确认」 | `2026-10-09` |
| 学历要求 | 大专/本科/硕士/博士 + 「及以上」 | `本科`（本科及以上） |
| 工作地点 | 「工作地点」段落 + 全国 100+ 城市词表 | `北京、上海、乌鲁木齐…` |
| 招聘岗位 | 「招聘岗位」段落 + 60+ 岗位词表 | `管培生、经办岗` |
| 需求专业 | 「招聘专业」段落 + 学科词表 | `信息科技、经济金融、法律` |
| 招聘人数 / 联系方式 | `N人` / 邮箱、座机、手机号 | `job@citicbank.com` |

另外还会输出：

- **文章类型判定**：`文字型` / `图文混合` / **`图片型`**（正文文字 <120 字且图片 ≥3 张时判定为图片型并明确告警）
- **关键句摘录**：含「投递/网申/截止/官网」语义的句子
- **判定依据**：每个投递链接为什么被选中（域名含 job/zhaopin、锚文本含「投递」、来自阅读原文……），可回溯、可质疑

### 链接打分规则（`rules.js` 里的 `scoreLink`）

| 情况 | 分值 |
| --- | --- |
| 已知招聘系统域名（hotjob.cn / 51job / mokahr / beisen…） | +45 |
| 域名含 `job|career|hr|zhaopin|recruit|campus|apply` | +40 |
| 锚文本含「投递 / 报名 / 网申 / 申请 / 简历」 | +30 |
| 来自「阅读原文」 | +18 |
| 邻近文字含「阅读原文」「投递」 | +10 ~ +12 |
| 微信站内文章链接 `mp.weixin.qq.com/s?...__biz=` | −60 |
| 锚文本是「分享/关注/二维码/广告」等噪声 | −35 |
| 图片 / 压缩包 / 文档直链 | −80 |

`≥25 分` 才算候选投递入口。微信的 `/mp/redirect?url=` 中间页、`?target=` 包装、二次编码都会被自动解包成真实地址。

## 四、准确度与已知限制

**测试覆盖：74 项检查全部通过。**

| 测试套件 | 项数 | 覆盖内容 |
| --- | --- | --- |
| `tests/run-tests.cjs` | 42 | 规则层单测 + 4 份夹具回归 + 格式化 + 健壮性（空输入 / 畸形 href / HTML 实体 / 防注入） |
| `tests/verify-manifest.cjs` | 15 | 清单自检：引用文件是否存在、注入顺序、图标有效性、`default_locale` 陷阱、快捷键格式 |
| `tests/verify-panel.cjs` | 9 | 用最小 DOM 桩**真实执行**面板挂载与渲染，含 XSS 转义验证 |
| `tests/verify-userscript.cjs` | 8 | 在**无 `module`/`document` 的纯净上下文**里加载打包后的 Userscript，并用真实夹具跑通 |

必须说清楚的限制：

1. **图片型推文是最大盲区。** 银行校招推文经常整篇就是一张长图，文字只有「点击阅读原文投递」。
   插件无法读图，此时它会（a）判定为图片型并告警，（b）把正文图片列出来让你点开看，（c）仍尽力从「阅读原文」拿到投递入口。
   要真正读图需要接 OCR，本插件刻意不联网、不上传，所以没做。
2. **截止年份可能是推断的。** 原文只写「10月25日」时，插件用**发布时间**的年份补全，并在界面上标「（年份据发布时间推断）」。如果推文是跨年转发的，请人工确认。
3. **机构名可能有「待确认」情况。** 标题模板命中时置信度为高；只能从正文推断时标「待确认」/「推测」。
4. **微信风控。** 批量模式的 fetch 走你浏览器的登录态；若微信返回「环境异常」验证页，勾选**标签页模式**——它在后台标签页真实打开文章再解析，成功率最高。
5. 结果是机器抽取，**投递前请以官方原文为准**。

## 五、开发

```bash
# 全部测试（74 项）
npm test

# 分项跑
node tests/run-tests.cjs         # 核心逻辑 + 夹具回归
node tests/verify-manifest.cjs   # 扩展清单自检
node tests/verify-panel.cjs      # 面板 UI 渲染（最小 DOM 桩）
node tests/verify-userscript.cjs # 打包后的 Userscript 制品

# 重新生成图标
python tools/make-icons.py

# 重新打包 Userscript（改了 src/ 之后必须重跑）
node tools/build-userscript.cjs
```

无构建步骤、无第三方依赖：`src/core/*.js` 用 UMD 包装，浏览器里当普通脚本加载，Node 里直接 `require`。
改完 `src/` 后，扩展直接刷新即可；**Userscript 需要重新运行打包脚本**。

### 目录结构

```
wechat-job-extractor/
├── manifest.json                 # MV3 清单
├── src/
│   ├── core/                     # ← 提取引擎（纯函数，可单测）
│   │   ├── rules.js              #   规则库：机构名/日期/学历/地点/链接打分
│   │   ├── parse.js              #   解析层：DOM 精确解析 + 无 DOM 的字符串解析
│   │   ├── fields.js             #   字段层：原始素材 → 结构化结果（含证据与置信度）
│   │   ├── format.js             #   输出层：Markdown / JSON / CSV / 纯链接
│   │   └── extract.js            #   统一入口 WJE.extract
│   ├── content/                  # 页面注入：Shadow DOM 面板 + 内容脚本
│   ├── popup/                    # 工具栏弹窗
│   ├── batch/                    # 批量抓取页（fetch 模式 + 标签页模式）
│   ├── options/                  # 设置页
│   └── background.js             # 右键菜单 / 快捷键
├── tests/
│   ├── fixtures/                 # 4 份夹具（含 3 家银行 2027 校招真实文案）
│   ├── run-tests.cjs             # 42 项测试
│   └── verify-userscript.cjs     # 打包制品端到端校验
├── tools/                        # 图标生成 + Userscript 打包
└── dist/                         # 分发产物
```

### 为什么 `parse.js` 有两套解析路径

- `parseDocument(document)`：内容脚本注入真实页面时用，选择器精确（`#js_content`、`#activity-name`、`#publish_time`、`msg_source_url`）。
- `parseHtml(html)`：批量抓取和**单元测试**用。批量模式在 Service Worker / 扩展页里没有可靠的 DOM 解析环境，且测试环境没有 jsdom —— 所以内置了一个轻量的 HTML 分词器（含 `<div id="js_content">` 的配平截取），零依赖。

两条路径产出同一种「原始素材」结构，下游字段抽取完全共用，因此**测试覆盖的就是线上逻辑**。

## 六、隐私

- 解析 100% 在本地浏览器完成，**不向任何服务器发送数据**，扩展没有任何网络上报。
- 唯一的网络请求是你在批量模式里主动发起的、对你粘贴的微信文章地址的抓取。
- 不使用远程代码，全部逻辑随扩展打包。

## 七、已有的同类工具（供参考）

市面上的方案大致三类，可以按需组合：

- **微信自带「收藏 + 标签」**：只能手动整理，不提取结构。
- **通用网页剪藏类扩展**（如简悦、Omnivore、腾讯文档剪藏）：长于「整篇存档」，但不理解「投递入口 / 截止时间」这类招聘语义，且对微信「阅读原文」跳转经常拿不到目标地址。
- **招聘聚合站/小程序**（如各类校招日历、银行招聘公众号矩阵）：信息全，但**投递链接指向聚合站自己的跳转页**，不是官方原文入口，且无法处理你手上这一篇具体推文。

本插件的定位是补这一块：**只做「单篇推文 → 官方投递入口 + 关键字段」这一件事**，结果可导出、可回溯。
